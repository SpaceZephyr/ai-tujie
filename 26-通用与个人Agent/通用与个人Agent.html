AI 原理图解 2601 / 07
先把名字说清楚

这不是官方分组

“通用 Agent”和“个人 Agent”是本文观察产品的两个角度，不是文中厂商的官方分类。同一个产品也可能同时具备两边的能力。

更有用的问题是：一个 Agent 主要为了完成各种临时任务而设计，还是为了长期服务同一个人而设计？前者更重视任务跨度，后者更重视持续上下文。

判断时可以盯四处：接什么任务、记住什么、在哪里运行、获得哪些权限。名字叫“个人助手”，也未必真有持久记忆；能写报告的 Agent，也可能连接个人日程。

分类是地图，不是产品能力的判决书。下面用现有产品看看这四个维度如何落地。

AI 原理图解 2602 / 07
通用任务型

先看能办多少事

这类产品接受一个目标，再跨工具完成过程：查资料、分析、生成文件、修改作品，最后交付可检查的结果。

Manus 2.0 的 Studio 覆盖文档、表格、网页、代码、视频等工作。它按项目需要加载能力，也能在授权后使用电脑上的文件、浏览器和应用。

ChatGPT Work 官方把它描述为能跨应用与文件执行任务的 Agent，可持续推进较长项目，并把资料整理成文档、演示、表格或网页。

这里的“通用”说的是任务范围广。这两款产品也会使用连接的上下文、记录任务进度，并由人控制重要操作；不能把它们理解成“完全不了解用户”。

AI 原理图解 2603 / 07
个人长期型

重点是一直跟着人

个人 Agent 更像一个持续在线的入口。今天在手机上说的事，换到电脑后还能接着聊；它会用到长期记忆、消息渠道和个人服务。

OpenClaw 的主会话把多个私聊入口汇入一条持续会话。长期记忆文件和每日笔记帮助它跨重置保留信息。工具权限决定它能不能处理文件、运行命令或发消息。

Manus 推出的 Cue 则为每个个人 Agent 提供独立身份、电脑和可设置的预算，面向日常服务与多 Agent 协作。官方称 Cue 目前是早期开放产品。

“个人”讲的是关系和上下文，也带来更高的权限管理要求。记住偏好，与代替人付款、发消息，是两种不同程度的授权。

四个比较维度

差别落在这四处

以下是两种产品重心的常见倾向，不是每款产品都照这个表设计。

看什么通用任务型常见重心个人长期型常见重心
任务广度跨多种工作，按目标选择工具围绕个人日常，反复处理熟悉的事
上下文任务材料、项目进度、连接应用偏好、历史、长期记忆、跨端会话
运行位置云端工作区，也可接入本机自托管网关或专属环境都存在
权限按任务批准访问和操作长期连接后更要限定动作范围

运行在本机，并不会自动变成个人 Agent；部署在云端，也不妨碍产品提供个人记忆。要看产品如何把这四件事组合起来。

AI 原理图解 2605 / 07
放进真实任务

先想自己要交什么

比如要做一次竞品研究，最后交付一份带出处的报告。任务有清晰起点和终点，工具可能跨网页、表格、文档，通用任务型的设计更贴近。

再比如每天从消息和日程里整理待办，记住常用联系人与偏好，第二天继续跟进。这里最难的是连续性和个人服务的连接，个人长期型的重心更贴近。

还有混合场景：长期助手记得背景，再调用研究、制表、写作能力完成一次项目。Manus 2.0 与 ChatGPT Work 都展示了这种交叉趋势。

真正需要提前定下来的，是哪些资料能读、哪些动作能自动做、什么动作要人确认。这些边界比产品标签更影响日常体验。

AI 原理图解 2606 / 07
放在一起看

先选任务，再给权限

如果只需要完成一件跨工具的大任务，先看交付质量：产物能否修改、来源能否核对、过程能否接着做。

如果希望 Agent 长期参与生活或工作，就要看它如何记忆、能连哪些服务、授权能否细分、会不会在关键动作前停下来。

从这些产品能看到一个方向：任务广度和个人上下文正被放到一起。与其争论属于哪一类，不如拿一件自己的真实任务试：给材料、给边界，再看结果和可控程度。

可以从只读资料开始，先看 Agent 怎样整理和引用；满意后再开放写入或对外动作。这样更容易看清楚，便利到底来自哪种能力，风险又落在哪项权限。
