Skill 怎么运行？

只露一行描述，用到才展开
“装得再多，平时也只占一行描述。”
AI 原理图解 1601 / 07
先认识一下

Skill：给 AI 的操作手册

Skill 是一个文件夹，里面写着做某一类事情的方法：按什么步骤、用什么格式、哪些不能做、参考什么例子。Agent 遇到这类任务，就翻开这本手册照着做。

Agent 指能自己调用工具干活的 AI，比如 Claude Code。一个 Skill 文件夹通常长这样：

SKILL.md：唯一必需的文件，开头写名字和描述，正文写步骤
references/：参考资料，比如规范、模板说明
scripts/：可以直接运行的脚本
assets/：模板、图片这类素材

改 Skill 就是改文档，不用碰代码，改完马上生效。它能让 AI 按更好的流程做事，但没法让 AI 变得更聪明，超出模型能力的活，手册写得再细也白搭。

AI 原理图解 1602 / 07
① 启动时

启动时：只看一行描述

Agent 一启动，会把每个 Skill 开头的名字和描述放进系统提示。一个 Skill 大约只占 100 个 Token。

系统提示是每次对话都会带上的那段背景说明。只放名字和描述，装 50 个 Skill 也就五千 Token 左右，占不了多少地方。

这一步里，SKILL.md 的正文、参考资料、脚本都还放在文件夹里，一个字都没读。这时候 Agent 眼里的 Skill 清单，大概就是这样几行：

pdf-processing：提取 PDF 里的文字和表格、填表、合并文件。处理 PDF，或者用户提到 PDF、表单时使用
xlsx：创建表格、分析数据、生成带图表的报告
pptx：做演示文稿、改幻灯片

这就是装了很多 Skill 也不怎么影响速度的原因：平时都只露一个名片。

AI 原理图解 1603 / 07
② 触发时

触发时：才读 SKILL.md

用户提出任务后，Agent 拿任务去比对各个 Skill 的描述。对上了，才用命令把这个 Skill 的 SKILL.md 正文读进来，这时候正文才开始占上下文。

官方建议正文控制在 5k Token 以内，写清楚流程、注意事项和例子。更长的资料拆到别的文件里，正文只写一句“需要时去看某某文件”。

官方文档里有个例子：

用户：把这个 PDF 里的文字提出来，总结一下
Agent：对上了 pdf-processing，读它的 SKILL.md
Agent：这次不用填表，表单说明那份文件就不读
Agent：照着正文里的步骤，把活干完

从头到尾，表单说明那份文件都没进过上下文。

AI 原理图解 1604 / 07
③ 用到时

用到时：再读附件、跑脚本

正文里提到的其他文件，Agent 真用到了才去读。没用到的，一个 Token 都不花。

脚本更省。Agent 直接运行脚本，脚本本身的代码不进上下文，进来的只有运行结果，比如一句“校验通过”，或者一条报错。比起让 AI 现场写一段同样的代码，又快又稳。

还是那个处理 PDF 的 Skill，这次只要提取文字：

SKILL.md：已读，触发时读进来
FORMS.md：不用填表，不读
REFERENCE.md：碰到不懂的接口才翻一下
scripts/fill_form.py：只运行，只看结果

所以一个 Skill 可以带上很多资料和脚本，放着不用都不占地方。

也正因为脚本能直接运行，官方特别提醒：来路不明的 Skill 别随便装，装之前把里面的文件和脚本都看一遍。

AI 原理图解 1605 / 07
写的时候

描述：决定它会不会被用上

描述就是开头那行 description。Agent 只靠它来判断要不要用一个 Skill。描述没写好，Skill 就一直躺在文件夹里，从来不会被用上。

官方的要求是：描述里要同时写清楚“它能做什么”和“什么时候该用”，最长 1024 个字符。名字最长 64 个字符，只能用小写字母、数字和连字符。

拿处理 PDF 的 Skill 对比一下：

写得太短：处理 PDF
写得清楚：提取 PDF 里的文字和表格、填表、合并文件。处理 PDF，或者用户提到 PDF、表单时使用

后一种把用户可能怎么说都写进去了，对上的机会大得多。写完可以换几种说法问问看，看它能不能被叫出来。

AI 原理图解 1606 / 07
放在一起看

三样东西：各管一段

Skill 经常和提示词、MCP 放在一起说，其实它们管的是三件事：

提示词：这一次对话里的要求，说完就过去了。比如“这篇写短一点”
Skill：某一类任务的做法，存成文件，用到才加载。比如“周报都按这个格式写”
MCP：接外部系统的统一接口，让 AI 够得着数据库、邮件这些。比如让它能查飞书文档

分不清该用哪个时，可以这么想：AI 不会做，是 Skill 的事；AI 够不着，是 MCP 的事。两个也常一起用，MCP 把能力接进来，Skill 告诉它怎么把这些能力组合成一件完整的事。

什么时候值得写成 Skill？一件事的做法要反复交代，说到第三遍，就该把它写下来，省得每次重讲。
