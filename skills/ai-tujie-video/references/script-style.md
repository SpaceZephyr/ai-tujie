# 口播稿怎么写

> 用在 ai-tujie 图组上：素材就是 source.md 里 7 页的文字。第 1 页给结论和总图，第 2–6 页各讲一块，第 7 页常是对比或总结。口播稿按「痛点 → 一句话答案 → 是什么 → 分步讲 → 怎么用/怎么选 → 收尾 + 第几篇 + 下一篇」排，一页图大约拆 2–3 句。下面的 8 种原型例子来自另一条视频，讲的是写法。

参考的是视频号「晓辉博士」（腾讯研究院袁晓辉）那种讲法：被问到一个问题，先直接给答案，再一层层讲现象、原因、做法；多讲自己怎么用，少下判断。语气平，像跟同事聊。

## 结构

| 段落 | 干什么 | 占比 |
|---|---|---|
| 痛点 | 用一个具体场景或问题开头，让人觉得「说的是我」 | 1–2 句 |
| 原因 | 为什么会这样，一句讲透，不绕 | 1–2 句 |
| 转折 | 引出做法，说清楚按什么分类 | 1 句 |
| 做法 | 一条一句到两句：什么情况用、怎么做、一个具体例子或数字 | 主体 |
| 怎么选 | 按场景给对应关系，帮人做决定 | 1 句 |
| 收尾 | 一句话说清这些做法共同在解决什么 + 我是谁、去哪找 | 1 句 |

例（8 种画原型）：
- 痛点：「画一个原型要多久？拖控件、对齐间距、标交互、写说明，一个页面，常常就是半天。」
- 原因：「慢在哪呢？从想法到别人能看的东西，中间全靠手一点一点搭。」
- 转折：「不过原型的起点各不一样……起点不同，顺手的做法也不同。我整理了八种。」
- 做法：「我自己用得最多的是截图。产品经理多数时候，是在现有页面上改一块……」
- 收尾：「八种方法，做的是同一件事：把脑子里的想法，尽快变成别人能看、能点、能讨论的东西。」

## 口吻

- 第一人称，讲自己的经验：「我自己用得最多的是」「我拿小红书试过，跑了半个多小时」。
- 用具体数字和例子代替形容词：「几十个代码文件」比「效果很好」有用。
- 每条做法的开头句式不一样：「手上只有想法，就……」「开会时白板上画了几个框……」「产品代码就在手边的话……」。不要八条都是「第 N 种，XX」。
- 不要：「首先/其次/最后」「值得注意的是」「不是 X 而是 Y」「赋能」「闭环」「一站式」；排比三连；结尾升华。
- 小停顿靠标点：该停的地方一定写逗号，配音靠标点补停顿。

## 少用英文

| 原文 | 口播里说 |
|---|---|
| skill | 技能 |
| PRD | 需求文档 |
| image2proto | 截图转原型 / 直接说「截一张图给它」 |
| url2proto | 给网址复刻 |
| MCP | 让 AI 直接操作设计工具 |
| Demo | 演示 |
| github.com/xxx | 不念，放画面上：「都放在我的开源仓库里」 |

能用中文说清楚的都用中文。但图组标题里的主角词（Skill、Agent、Token、MCP、RAG）照原样说，微软音色念英文没问题，换成中文反而对不上画面。英文缩写念不准时写成读音（「R A G」）。

## 字数和分场

- 云扬 +15% 收紧停顿后，成片每秒约 6 字，每场额外约 0.35 秒。
- 2 分钟 ≈ 700 字 / 3 分钟 ≈ 1050 字。16 句左右一条正好。
- lines.json 每句 30–80 字，一句一场。8 种方法类内容：开头 3 场 + 每种 1 场 + 怎么选 1 场 + 收尾 1 场。

## 写完自查

1. 读出声，有没有喘不上气的长句。
2. 每场能不能想出 3 个「念到这个词，画面出现这个东西」的点；想不出说明太空，改得更具体。
3. 有没有事实是 facts.md 里没有的（自己编的数字删掉）。
4. 有没有吞字风险：云希会把「这一次」念成「这次」，改说「这次对话」这类不易吞的说法；`finalize.py` 报漏字时先单独截那句再识别确认。
