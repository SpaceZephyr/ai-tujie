在 MCP 之前

老办法：一个一个写

大模型自己一个接口也调不了。它写得出“帮我查订单”，真去查的，是旁边开发写的代码。

麻烦在接口这一头。一个 AI 应用要接一个新服务，就得为它单独写一套适配代码：调用什么格式、参数叫什么名字、返回怎么解析，全都各定各的。服务一改版，这套代码还得跟着改。

5 个应用
每个都自己写
×
5 个服务
格式各不相同
25 套集成
谁也复用不了谁的（示意）

每家都这么写，写的还都不一样。应用换一代、服务改一版，都要重来。接入慢，卡在格式不统一上。

AI 原理图解 1702 / 07
MCP 的三个角色

三个角色：各管一段

MCP 把一次接入拆成三个角色：Host 是 AI 应用，Client 是它开出的连接，Server 是包装好的服务。

三个名字看着绕，关系一句话就能说清：Host 想接多少个服务，就在自己里面开多少个 Client，每个 Client 认一个 Server。三个角色分别是：

Host：AI 应用本身，Claude Code、Claude 桌面端、VS Code 都算，负责协调所有的连接
Client：Host 里开出来的一段连接程序，一个 Client 只连一个 Server，一对一
Server：把外部系统的能力按统一格式包好的程序，跑在本机、放在远程都行

连接方式也是规定好的：Server 跑在本机的，用进程之间最普通的传话方式；放在远程的，走 HTTP。怎么连不用操心，Host 都按同一套来。

装的时候其实只需要关心 Server：装好一个 Server，所有支持 MCP 的应用都能连它。

AI 原理图解 1703 / 07
Server 里有什么

Server：三样东西

一个 MCP Server 对外提供的东西分三类：能调的工具 tools、能读的资源 resources、能复用的提示模板 prompts。

三类东西各有各的用途：

tools（工具）：AI 能调用的操作，查一个订单、发一条消息、改一个文件
resources（资源）：给 AI 读的数据，文件内容、数据库记录
prompts（提示模板）：写好的指令模板，把一种固定问法复用起来

取用的方法也是统一的：先列清单，再按需取用、执行。接哪个 Server，动作都一样，应用不用为某一家单独学一遍。Server 上的工具变了，还会主动通知应用，不用每次重新拉清单。

真正值钱的是生态。GitHub、飞书、Notion 这些服务陆续原生提供 MCP 接口，Claude、ChatGPT、VS Code、Cursor 这些应用也都支持。接一个新服务，从写一套代码，变成填一份配置。

AI 原理图解 1704 / 07
从提问到结果

一次调用：四步走

以“查一个订单”为例，从提问到答案，中间走过四步：

01
拿清单
连上 Server 后，Client 先取回工具清单：每个工具的名字、参数、说明。说明写得好不好，直接影响它用得对不对。
02
写请求最容易误解
模型在回答里写出一段结构化文字：“调用 query_order，参数 A1024”。它只写这段字，不动手。
03
去执行
Client 把请求转给 Server，Server 里的代码真的去查、去改、去发。
04
回结果
结果拼回上下文，模型看到后再想下一步。失败也要返回，它才知道换个参数重试。
模型从头到尾只写文字，动手执行的，是 Server 里的代码。
AI 原理图解 1705 / 07
和 Skill 的关系

两回事：方法和接口

Skill 和 MCP 经常被混着说，其实一个管“怎么做”，一个管“怎么接”。Skill 是操作手册，MCP 是插线板：手册教人怎么操作，插线板让人通上电。

1
它不会做，用 Skill
要它按流程、按格式、按规范干活。这是知识层面的事，改文档就生效，改起来便宜。
2
它够不着，用 MCP
要它真的去查数据库、发消息、操作系统。这是连接层面的事，系统有现成接口就连，没有就得自己写。

改起来也不一样：改 Skill 是改文档，改完即生效；接 MCP 是装接口，装好一次，所有支持的应用都能连。

分不清的时候问一句：这个问题，给它一份说明能解决，还是给它一个接口才能解决。

两者常常一起用：MCP 提供一组外部能力，Skill 教它把这些能力组合成一件完整的事。

AI 原理图解 1706 / 07
代价

代价：占窗口，也有风险

MCP 只把接口摆到模型面前，不保证它用得对。装多少、装哪些，还得自己判断。

先算上下文的账。每个 Server 的工具清单都要拼进上下文，装得越多，窗口占得越满，模型还更容易在几十个工具里挑错。几十个塞进去，效果往往不如三个写清楚的。

再算安全的账。第三方 Server 返回的内容里，可能藏着提示注入：一段伪装成数据的文字，诱导模型去调不该调的工具。装得越多、来源越杂，这条边界越要守住。

几条经验：

只接一两个服务：写个简单工具就够，不必上整套 MCP
服务多、要统一管：这时候 MCP 才划算
装之前过一遍：工具说明清不清楚、权限怎么配、来源可不可信
