AI 原理图解 2001 / 07
为什么要搭

模型没读过你的资料

聊得再顺，模型也只知道训练时见过的东西。公司的制度、项目的来龙去脉、自己攒的笔记，训练语料里都没有，问它等于问一个没进过门的外人。

最直接的办法是每次把资料粘进对话框。粘一两次还行，次数多了就乱了：忘了粘哪段，粘的是旧版本，内容一长还超出上下文窗口，前面的被挤掉。

知识库要解决的就是这件事：资料放在一个固定的文件夹里，整理成模型读得懂的样子，每次提问，AI 自己去翻，不用人来回搬。搭一次，之后每一回都用得上。

这件事的重点在整理，不在技术。下面三页按顺序讲：三种做法长什么样、大多数人在哪一档就够、资料具体怎么理。

粘贴式问答每次都要人找资料、人复制、人核对版本；知识库把这三件事一次固定下来，整理一遍，之后的每次提问都在用这份整理。
AI 原理图解 2002 / 07
三种做法

三档做法，先看再选

同一个目标，做法分三档，区别只在AI 怎么找到资料。先看清楚三档各是什么，再决定停在哪一档。

01
文件夹直接读
资料全是 Markdown，放进一个文件夹，AI 按文件名和目录自己翻。零成本，顺手就能开始。
02
索引 + 按需读性价比最高
顶上放一个索引文件，一行写清每个文件讲什么。AI 先查索引，再打开真正要看的两三个文件，不用全翻一遍。
03
向量库检索
资料切块、算成向量、存进向量库，提问时按语义相似度捞片段回来。效果最好，工程量也最大。

三档是叠加关系。第二档的索引文件，第一档也用得上；第三档通常等资料多到翻不过来时再上，RAG 检索管线内部的运作方式，系列里那篇 RAG 会单独讲。

AI 原理图解 2003 / 07
大多数人停在这里

多数人停在第一档就够了

把资料整理成一个 Markdown 文件夹，用 Claude Code 或 Cursor 打开，直接开始问答。个人和几人小团队的知识库，到这里基本就够用了。

这两样工具找文件的方式和人差不多：先看文件名和目录，再打开值得读的文件。文件夹本身就是一个够用的知识库，缺的只是整理。

Cursor 在打开项目时会自动给文件建索引，问答时做语义搜索，官方的评测说平均能把回答准确率提升 12.5%。Claude Code 每次会话开始会读一份 CLAUDE.md，把文件夹里有什么、文件怎么分类写进去，翻资料会快很多。

什么时候考虑升级：提问开始变慢、答案开始抓不准文件、文件夹大到自己都记不清里面有什么。那时候再往第二档、第三档走。

第一档不用装任何新东西，资料在哪，知识库就在哪；要做的只是把散落的文档收进一个文件夹，理一遍名字。
AI 原理图解 2004 / 07
动手整理

资料先理成读得懂的样子

AI 找资料靠两样东西：文件名，和文件开头几行。整理就是在这两处下功夫。

三条规矩，都是从这两处长出来的：

一件事一个文件：会议纪要别和项目计划混在一个文件里，混了的文件两头都搜不到。
文件名写清主题和日期：AI 先扫文件名再决定开哪个，随手写的名字等于没给线索。
顶上放一个索引文件：一行一个条目，写明每个文件讲什么。AI 先查索引再翻文件，少走弯路。

Claude Code 的官方文档还有一条建议：给 AI 看的说明文件保持在两百行以内，只写本来要反复解释的事。索引文件同理，越短越灵，塞成一部长篇，AI 反而抓不住重点。

索引条目长什么样，一行就够：项目背景.md —— 立项原因、给谁看、更新到 9 月。名字、主题、新鲜度，三样齐了，AI 一眼就知道该不该打开。

AI 原理图解 2005 / 07
升级的时机

什么时候才需要向量检索

向量检索是把资料切成片段、算成表达意思的向量，提问时按意思相近捞回来。它要换一整套维护方式，上之前先过三条线：

1
资料量
Anthropic 给过一条参考线：资料不到 20 万 Token、大约五百页，整份放进上下文反而更省事也更准；多出好几倍，才谈检索。
2
检索准确度
搜型号、编号、人名这类精确词，关键词检索比向量灵。向量捞回来的常常是意思像、但偏偏不是要找的那份。
3
维护成本
资料每改一次，向量要重算一遍，还得有人管同步。长期没人维护的向量库，捞出来的全是过时结果。

三条里两条没过，答案很简单：回第一档，把省下的力气花在整理资料上。

AI 原理图解 2006 / 07
常见的坑

坑大多出在资料本身

知识库搭坏了，回过头看，问题几乎都出在整理上。三个最常见的：

一个文件塞太多：几百行混装一个文件，AI 要么读不完，要么读到一堆不相干的。
命名随手写：“新建文档”“最终版2”，AI 靠文件名找资料，这样的名字等于没给门牌。
建完不更新：知识库最大的敌人是过期。资料变了文件不跟着改，AI 会一本正经地拿旧答案回答。

把这套图连起来看：先定“模型没读过我的资料”这个前提，再按三档挑做法，把力气花在整理上，向量检索留给资料真正多起来的那天。一句话：先把它当成整理资料的问题，再当成技术问题。
