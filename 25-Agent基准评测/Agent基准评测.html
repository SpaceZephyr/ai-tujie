公开考试

Benchmark 是什么

Benchmark 是一套可重复使用的标准化测试。把 Agent 放进同一批任务里，按约定规则检查结果，才能比较不同方案。

一场考试至少有四样东西：

题目：输入材料和要求完成的任务
环境：可用的文件、网页、工具或代码仓库
限制：时间、调用次数或运行成本
判分：用答案、测试或最终状态验收

榜单通常只展示最后的分数。要读懂这个数字，得先知道题目和判分规则测的是哪种能力。

代码 Agent

SWE-bench 考修代码

SWE-bench 的题目来自真实 GitHub 项目。Agent 拿到代码仓库和问题描述，要提交一个能解决问题的补丁。

评测程序会把补丁放回对应的项目环境，再运行测试，看原来失败的问题是否解决，也检查原有功能有没有被破坏。这里考的是读代码、定位问题、修改并验证。

SWE-bench Verified 是经过人工确认可解决的一组题。看榜单时，先确认写的是哪个数据集和版本。

代码题拿高分，说明这类修复任务做得好。若要评估订票、整理资料或跨应用办事，还需要相应的题目。

通用助理

GAIA 考查找与推理

GAIA 给通用助理出真实世界的问题。题目可能附带文件，需要浏览网页、读表格或图片，再把分散的信息连起来。

GAIA 特意把答案设计得简短、明确，方便对照标准答案判分。Agent 可以用不同路线找到答案，最后仍要给出可核对的结果。

这类题主要看检索、理解多种材料、推理和工具使用。原论文也说明，它没有覆盖下单、发帖、付款等会改变外部世界的操作。

因此，GAIA 分数能帮助看通用信息任务；要知道 Agent 能否可靠执行某项业务动作，还得另设考场。

AI 原理图解 2504 / 07
读分数

同一题也能考出差别

评测 Agent 时，测到的是模型、工具和执行程序一起工作的结果。同一个模型，换了可用工具或调用方式，成绩也可能变化。

比较两个结果时，先把这几件事摆在一起看：

题目版本：是不是同一批题
工具与环境：是否能搜索、读文件、运行代码
预算：允许多少时间和调用
运行次数：一次成绩，还是多次后的统计

Agent 的输出有波动。同一题跑多次、每次重置环境，再看通过率，才更容易分清稳定能力和偶然跑通。

AI 原理图解 2505 / 07
自己的考场

真实业务要自己出题

公开基准能比较一类能力。要判断 Agent 能不能用于自己的业务，可以把日常任务和真实失败案例整理成私有测试集。

例如“整理客户反馈”：给定十条原始记录和一张空表，要求分类并填表。判分时核对分类依据、表格最终状态，还要检查有没有改原文或擅自发送。

每道题保存输入、初始环境、允许的动作、验收条件。运行前重置环境；运行后核对产物和关键工具记录。

这样做的好处很直接：改了提示词或工具后，能拿同一批业务任务重新测，看到进步和退步。

AI 原理图解 2506 / 07
放在一起看

榜单该怎么读

看到“Agent 排名第一”，先找到它参加了哪场考试。题目、工具、预算、判分和运行次数，少看一项都可能误读分数。

SWE-bench：优先看代码修复能力
GAIA：优先看信息检索与推理能力
自己的任务集：看产品要交付的工作是否稳定完成

公开基准帮忙缩小候选范围；最后仍要用自己的任务和验收标准试一遍。上线后遇到的新失败，也应补进测试集。
