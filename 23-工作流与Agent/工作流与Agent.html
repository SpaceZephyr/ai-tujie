AI 原理图解 2301 / 07
先看区别

谁来决定下一步

固定工作流预先写好步骤和分支；Agent 会看中途结果，再决定下一步做什么。

例如文章排版，读取正文、套模板、检查尺寸、导出图片，这些步骤都能提前写清。

换成调查一个开放问题，下一步要查什么，往往取决于刚找到的证据。此时让模型动态选择工具更有用。

两边都可能调用模型和工具。区别在于流程由程序预先排好，还是由模型在任务中继续决定。

先分清决策权在哪，比给系统贴上“Agent”标签更能看懂它怎么工作。

AI 原理图解 2302 / 07
步骤已知

固定工作流更稳

当输入、顺序和完成条件稳定，固定流程容易复现，也容易查是哪一步出了错。

例如每周收到一份表：先校验列名，再汇总数据，最后按固定格式生成报告。中间可以用模型写摘要。

每一步的输入输出都明确，失败时可以只重跑这一段。人工也容易在指定位置检查。

这类任务加入 Agent 循环，模型可能每次挑不同路线，让成本、耗时和结果一起变得难预测。

把重复动作固定下来，并不妨碍某一步使用 AI；关键是不用让模型重新发明整个流程。

AI 原理图解 2303 / 07
路径未知

开放任务才给它选择权

有些任务只知道目标，无法预先列出所有步骤。Agent 可以根据工具结果改计划。

例如查一个产品为何频繁报错，先读日志；日志指向哪里，再决定查配置、代码还是服务状态。

模型需要能观察环境、调用工具、发现失败并继续尝试，直到达到完成条件或停止上限。

这类自由度能处理意外情况，也会多花时间和调用费用。错误还可能沿着后续步骤放大。

所以要给清楚目标、可用工具与停止条件，让动态选择有边界。

AI 原理图解 2304 / 07
两者能混用

固定骨架里留一段弹性

一条流程里，有些环节规则明确，有些必须临场判断。把两者拼在一起并不矛盾。

例如内容生产可以固定“收集素材、写大纲、审稿、导出”四站，但让模型在收集素材时决定追哪条线索。

审稿标准、文件位置和交付格式由流程锁住；资料不足时如何补查，则交给模型判断。

这样既保留可复现的交接点，也给复杂环节留了探索空间。

流程是否好用，要看最终产物与中间失败能否被看见，而不是看用了多少层智能体。

AI 原理图解 2305 / 07
代价在哪

自由度会带来额外账单

每次动态决定下一步，往往意味着再调一次模型、再走一次工具，也多一次出错机会。

固定流程的边界比较清楚：输入、输出、条件都事先可见。Agent 则可能绕路，或者在错误结果上继续推断。

开放任务值得付这笔成本，因为下一步本来就写不死。简单任务若能一次完成，硬套多轮循环反而拖慢。

不管哪种路线，都要定义完成条件，并检查真实状态。模型说“已完成”不等于文件已经生成。

选择架构的目的，是让任务更可靠地完成，不是让系统看起来更复杂。

AI 原理图解 2306 / 07
最后怎么选

先问步骤能否写死

面对新任务，先写出理想的输入、输出和验收方式，再看中间步骤有多少未知。

能列出稳定的步骤与分支，就用固定工作流；只有部分未知，把那一段交给模型动态处理。

路径经常被新证据改写、工具选择无法预先列完，才考虑完整的 Agent 循环。

无论选哪条路，都给失败留出口：重试上限、人工接管和最终结果核对。

从最简单能工作的结构起步，测试确实不够用时，再增加自主决策。
